# 访谈清单：把用户的口径变成 dashboard.yaml

按 4 轮问，每轮一次问完这一轮的问题，用户答不上的用括号里的默认值。能从用户给的表结构 / 样例 SQL / 文档里读出来的，直接填，只把推断结果给用户确认，不要重复问。

每轮结束，把这一轮写进 yaml 的片段贴给用户看一眼再进下一轮。

## 第 1 轮：数据在哪（决定 source 段）

1. 数据放在哪？
   - 本地文件（CSV / Parquet / DuckDB）→ `source.type: duckdb`
   - 能用连接串连上的库（Postgres / MySQL / Trino / ClickHouse / Hive-Spark）→ `sqlalchemy`
   - 只能通过公司内部工具 / CLI / HTTP 接口跑 SQL → `command`（让用户给一个「从 stdin 读 SQL、往 stdout 打 JSON」的命令；没有就替用户写个包装脚本，模板见 `config-schema.md`「command 通道」）
2. SQL 方言？（按上一题推断：duckdb / postgres / mysql / trino / clickhouse / spark。Hive、Spark SQL 一类都选 spark）
3. 凭据怎么给？连接串 / token 只放 `.env`，**不写进 yaml，不在对话里回显**。command 通道如果依赖某个登录态文件，记下路径填 `auth_file`，页面会提醒过期。
4. 单条查询大概多久能跑完？（默认 `timeout_s: 900`；数仓慢就调大）结果最多多少行？（默认 `max_rows: 5000`，到上限会报错，不会用截断的结果）

## 第 2 轮：表长什么样（决定 table / scopes / subscope）

先请用户贴 DDL 或 `DESCRIBE` 结果 + 3 行样例。然后确认：

1. 一行是什么？必须是「一行一个事件」的明细表。若是宽表（一行一个用户一天），先跟用户确认能否换成事件明细；不能就停下说明本看板不适用。
2. 去重单位列（设备 / 用户 id）→ `table.device`
3. 日期分区列 + 类型 → `table.date`、`date_type`（int `20261019` / date / string，string 还要 `date_format`）
4. 事件名列 → `table.event`
5. 筛选会用到哪些列？按 string / number / bool 列进 `table.columns`。**这是白名单**：指标库只能在这些列上加条件。敏感列（手机号、IP、精确定位、设备指纹等）不要放进来。
6. 要按什么切范围？（默认只有一个「全部」）每个范围给一个 SQL where 片段，如 `platform = 'android'`。
7. 范围下要不要再按某列细分？（国家、渠道……）要的话列出全部可选值，它也是白名单。

## 第 3 轮：日常漏斗口径（决定 funnel 段）

1. 按顺序列出漏斗步骤，每步：事件名 +（可选）附加条件。例：「有效播放 = play_end 且 is_valid」。
   - 某步是「页面入口前」的公共步骤、不分入口吗？→ `shared: true`
   - 只想单独计数、不进链路的事件（无结果、报错）→ `extra_steps`
2. 不同入口要分开看吗？（默认不分，只有一档「全量」）分的话每档一个 where；有的入口天然缺某一步（如桌面组件直达、没有「打开搜索」）→ 该档 `skip` 这一步。要「全量」档就用 `union` 合并成员档（成员档 where 要互斥）。
3. 哪几步是核心链路（加粗、趋势图默认画）？`core`
4. 「较 X」列以哪一步为基准？`anchor`（默认核心链路第一步）
5. 顶部指标卡：第一张是北极星，写成「分子步 ÷ 分母步」（都是独立去重 UV）。再要 2~4 张。越低越好的标 `lower_is_better`。
6. 数据什么时候算完整？用哪一步判断、跟前 7 天中位数比低于多少算不完整？（默认锚点步、0.6）
7. 要不要按某个数值列分桶看转化（如位置 CTR）？要活跃用户表算渗透率吗？（都可选）
8. 每天几点拉昨天的数？（默认 09:40；要晚于数仓产出时间）

## 第 4 轮：实验回收习惯（决定 experiment / metrics 段）

1. 分组信息在哪一列、长什么样？
   - 列值就是组号 → `match: equals`
   - 一个字段里塞多个实验的组号（如 `",101,205,"`、JSON 数组字符串）→ `match: like` + `pattern`，`{id}` 是组号占位，要能唯一匹配（`%,{id},%` 比 `%{id}%` 安全，后者会让 `10` 命中 `101`）
2. 哪些事件带分组号？只有部分事件带的话列进 `identify_events`：设备当天有这些事件且带组号，才算进组。
3. 回收节奏（默认 第 2 天查生效 / 第 3 天判止损 / 第 7 天中期 / 第 14 天出结论）。
4. 显著性水平（默认 α = 0.05）、SRM 阈值（默认 p < 0.001 判分流不均）、人均类指标的 P99 封顶取上线前几天（默认 7）。
5. 预置指标：每个问清
   - 角色：北极星（1 个）/ 过程 / 护栏
   - 分子 / 分母：事件 + 筛选 + 计数方式（uv 设备去重 / pv 条数 / sum:列 求和）
   - 分子是否只算分母里的设备（比率类一般是）
   - 是否越低越好、是否要 P99 封顶（人均次数、时长类要）
   - 分位数指标（耗时 P50/P90）：事件、列、分位点
   北极星的口径要和日常漏斗第一张卡片一致，用户说法不一致时指出来请用户定。

## 收尾

1. 写出完整 `dashboard.yaml`，跑 `python3 template/tools/check_config.py --config <yaml>` 直到通过。
2. 用 `scripts/generate.py <目录> --config <yaml> --probe` 生成；自检里有「没有数据」的步骤，逐个跟用户核对事件名。
3. 告诉用户：怎么启动、第一次点「从数据源刷新」、怎么新建一个实验回收、指标库怎么加指标、服务常驻用 `tools/install_service.py`。
