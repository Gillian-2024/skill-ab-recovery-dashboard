# 口径与回收的最佳实践

看板把下面这些规则做成了默认行为；访谈时用户提出相反做法，先讲清代价再按用户的决定来。

## 日常漏斗

- **UV 不能相减、相邻两步独立去重 UV 不能相除。** 独立去重的「步 B ÷ 步 A」可能 > 100%（有人没走 A 直接到 B）。逐步转化用包含式漏斗（设备-天、当天走过前面所有步）；顶部指标卡用独立去重 UV 的比值，并在卡片上写明口径。
- **北极星在日常和实验里用同一个口径。** 实验回收的「分子只算分母设备」在窗口级取并集；日常卡片是逐日比值。两者对不上时先查是不是分子里有大量「不在分母里」的设备。
- **比较前确认分母相同。** 不同档、不同范围、不同日期窗口的比例并排看，要先确认它们的分母事件和过滤一致。
- **看到台阶先查数据，再讲业务。** 原始 UV 表里与前一日相差 2 倍以上会标「台阶」：先看是否埋点版本、上报通道、分区未落满，再归因到策略。
- **当天数据不完整就不读。** `completeness` 按锚点步对比前 7 天中位数；不完整的天不进窗口日均，系统定时重试。
- **「较上一周」只作描述。** 它是两段窗口的转化差，不做显著性；需要结论时开实验。

## 实验回收

- **开窗前先算 MDE。** 总览表的 MDE 列 = 当前样本下可测出的最小差异；目标效果小于 MDE 的实验，跑满也测不出来，应该加流量或延长窗口，而不是等。
- **四个节点各看各的。** 查生效只看进组和分流；判止损只看北极星 / 护栏是否「整个置信区间落在变差一侧」，不读收益；中期读数不作推全结论；出结论读当前累计行。
- **分流先过 SRM。** 卡方 p < `srm_p` 时整份读数不可信，先查分流配置、进组口径（`identify_events`）、跨组设备。
- **标准误按分流单位聚类。** 分流单位是设备，就按设备聚类（delta method），不能把设备-天当独立样本。
- **显著 ≠ 量级可信。** 显著但 |Δ| < MDE 的，结论写「方向为正 / 负，幅度不可信」，不引用具体数值。
- **逐日同向天数不作判据。** 「连续 5 天为正」不等于显著，逐日行只看稳定性和异常日。
- **护栏劣化先拆解再阻塞。** 护栏显著变差时，先拆机制（哪个子事件）、分布（哪部分用户）、分母（是否分母变了），确认是真劣化再止损。
- **人均类指标做 P99 封顶。** 封顶值取上线日之前 N 天单设备单天的 P99，算一次写死，避免实验本身改变封顶线。
- **每次回收重新审指标。** 上一个实验的指标组合不一定适合这次的策略形态；开新回收时按策略作用的环节重新勾选。
- **看板只给数据。** 结论提要不出「建议上线 / 建议推全」，采纳与否由人判断。

## 接入与运维

- **结果行数到上限就报错。** 不接受被截断的结果；遇到就缩短窗口或调大 `max_rows`。
- **凭据只放 `.env` 或外部登录态**，不进 yaml、不进仓库、不在对话里回显。
- **服务只监听本机。** 页面没有登录；写接口只收同源的 JSON 请求，挡住其他网页借浏览器身份触发跑数。不要改成 `0.0.0.0` 共享给别人，要共享请部署带鉴权的版本。
- **筛选列走白名单。** `table.columns` 里只放业务上需要筛选的列；敏感字段不要进白名单。
